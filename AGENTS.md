# AGENTS.md — Инструкции для Codex

## 1. Назначение

Проект: **Excel AI Agent**.

Полное техническое задание находится в файле `PRD.md` в корне проекта.

Перед началом работы обязательно прочитай `PRD.md` полностью. При противоречии между требованиями PRD и текущей реализацией сообщи пользователю о проблеме и запроси решение.

## 2. Порядок работы

1. Изучи PRD и текущее состояние проекта.
2. Составь план реализации по этапам.
3. Не создавай и не изменяй файлы до утверждения первоначального плана пользователем.
4. Реализуй только один согласованный этап за раз.
5. После этапа выполни доступные проверки и тесты.
6. Сообщи об изменённых файлах, результатах тестирования и обнаруженных проблемах.
7. Не переходи к следующему этапу без явного подтверждения пользователя.

## 3. Технические правила

- Основной язык: Python 3.12.
- Интерфейс: Streamlit.
- AI-агент: OpenAI Responses API с function calling.
- Excel: только через существующий Excel MCP Server по STDIO.
- Все чтения и изменения содержимого Excel выполнять исключительно через MCP.
- Не использовать `openpyxl`, `pandas` или аналогичные библиотеки для прямого доступа к Excel в приложении.
- Не изменять внешний проект `excel-mcp`.
- MCP-сессия открывается на одну непрерывную операцию и закрывается до ожидания подтверждения пользователя.
- Получать схемы инструментов через MCP `list_tools()`.
- Предоставлять модели только разрешённые инструменты.
- Контроллер обязан проверять аргументы, разрешения, подтверждения и лимиты.
- Не выполнять изменение статуса до явного подтверждения.
- Не сообщать об успешной записи до проверки результата повторным чтением через MCP.
- Не повторять автоматически запись при неизвестном результате.
- Хранить чат и журнал операций в `st.session_state`.
- Журнал должен отражать реальные MCP-вызовы.

## 4. Ограничения проекта

Не добавляй без согласования:

- авторизацию и многопользовательский режим;
- SQL или векторные базы данных;
- RAG;
- Docker и облачный деплой;
- поддержку произвольных Excel-файлов;
- массовые изменения заявок;
- дополнительные интеграции.

Сохраняй проект небольшим, понятным и пригодным для обучения.

## 5. Безопасность

- Не записывай API-ключи в код или Git.
- Используй `.env` и `.env.example`.
- Не передавай секреты в браузер или журнал.
- Не изменяй существующий Excel-файл при повторной инициализации.
- Сброс тестовых данных допускается только после явного подтверждения.
- Не изменяй файлы вне рабочего проекта, кроме разрешённого взаимодействия с внешним MCP Server.

## 6. Отчёт после каждого этапа

Представляй краткий отчёт:

1. Что реализовано.
2. Какие файлы созданы или изменены.
3. Какие тесты выполнены и их результаты.
4. Какие проблемы обнаружены.
5. Что предлагается делать на следующем этапе.

После отчёта ожидай подтверждения пользователя.
