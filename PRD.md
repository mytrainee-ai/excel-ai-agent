## 1. Цель проекта

Разработать приложение **Excel AI Agent** для управления заявками технической поддержки через чат на русском языке.

Пользователь формулирует запрос естественным языком. AI-агент с помощью OpenAI Responses API самостоятельно выбирает инструменты существующего Excel MCP Server, выполняет разрешённые операции и сообщает результат.

Приложение должно наглядно демонстрировать цепочку:

**Пользователь → Streamlit → AI-агент → контроллер → MCP Client → Excel MCP Server → Excel-файл → результат.**

Основная учебная задача — продемонстрировать реальную работу AI-агента с MCP, включая выбор инструментов, передачу аргументов, выполнение вызовов и обработку результатов.

## 6. Принцип работы с Excel

**Абсолютно все операции с содержимым Excel должны выполняться через MCP.**

Это включает создание книги, листа, чтение, запись, проверку, обновление таблицы, инициализацию и сброс данных.

В приложении запрещено непосредственно читать или изменять Excel с помощью `openpyxl`, `pandas`, `xlwings` и аналогичных библиотек.

Допускается обработка Python-данных, уже полученных через MCP, включая фильтрацию, вычисление ID и сравнение записей.

Проверка существования файла средствами файловой системы допускается; содержимое книги читается только через MCP.

## 7. MCP Client

Использовать официальный Python MCP SDK:

```python
from mcp import ClientSession
from mcp.client.stdio import stdio_client, StdioServerParameters
```

MCP Client должен:

- запускать внешний сервер через STDIO;
- выполнять `initialize()`;
- получать инструменты через `list_tools()`;
- вызывать инструменты через `call_tool()`;
- возвращать нормализованные результаты;
- корректно закрывать соединение;
- регистрировать фактические вызовы в журнале.

Учитывать поля Python SDK:

- `input_schema` у описания инструмента;
- `structured_content` у результата;
- `content` у результата;
- `is_error` у результата.

Если доступен корректный `structured_content`, использовать его. Иначе обрабатывать текстовые блоки `content`.

При `is_error=True` или прикладном `success=False` не считать операцию успешной.

### 7.1. MCP-сессии

Использовать решение U1: **одна новая MCP-сессия на непрерывную операцию**.

В одной сессии разрешены несколько последовательных вызовов инструментов.

При ожидании подтверждения изменения статуса MCP-сессия должна быть закрыта.

После подтверждения открывается новая сессия.

Не поддерживать постоянную MCP-сессию на всё время работы Streamlit.

### 7.2. Инструменты

Ранее на сервере обнаружены:

- read_range

Для рабочего агента разрешить только необходимые инструменты чтения и записи:

Для отдельной инициализации разрешить `create_workbook`, `create_sheet` и необходимые инструменты чтения/записи.

Модель не должна получать инструменты удаления листов, произвольного форматирования или изменения структуры книги.

Реальные параметры инструментов обязательно исследовать через `list_tools()`, не предполагать их названия.

## 8. AI-агент

Использовать **OpenAI Responses API** и function calling.

Основной вызов:

```python
client.responses.create(...)
```

Модель задаётся через конфигурацию `OPENAI_MODEL`.

AI-агент должен самостоятельно:

1. Понимать намерение пользователя.
2. Определять необходимые действия.
3. Выбирать разрешённые инструменты.
4. Формировать аргументы.
5. Получать результаты MCP.
6. При необходимости выполнять дополнительные вызовы.
7. Формировать итоговый ответ.

Не заменять агента жёстким набором обработчиков пользовательских фраз.

### 8.1. Динамические схемы

При подключении к MCP:

1. Получить инструменты через `list_tools()`.
2. Отобрать разрешённые.
3. Преобразовать реальные JSON Schema в формат function tools Responses API.
4. Передать их модели.
5. Сопоставлять вызовы модели с MCP-инструментами.

Проверять совместимость схем с выбранным режимом Responses API.

Не ослаблять проверки контроллера при преобразовании схем.

### 8.2. Цикл агента

После вызова Responses API:

- если модель сформировала окончательный ответ — вернуть его;
- если модель запросила инструмент — проверить запрос;
- при допустимом запросе вызвать MCP;
- передать фактический результат модели;
- продолжить цикл до завершения или достижения лимита.

Служебные `initialize()` и `list_tools()` не входят в лимит рабочих вызовов MCP.

### 8.3. System prompt

Создать отдельный системный промпт.

Он должен устанавливать:

- роль AI-помощника технической поддержки;
- русский язык общения;
- работу только с заявками;
- использование MCP как единственного источника Excel-данных;
- запрет выдумывать записи и результаты;
- необходимость уточнять неоднозначные запросы;
- допустимые статусы;
- необходимость подтверждения изменений;
- запрет объявлять неподтверждённую запись успешной.

Системный промпт не заменяет проверки контроллера.

## 9. Контроллер безопасности

Контроллер располагается между AI-агентом и MCP Client.

Он обязан проверять:

- имя инструмента по allowlist;
- обязательные аргументы;
- типы и допустимые значения;
- путь к файлу;
- имя листа;
- диапазоны ячеек;
- разрешённость изменения;
- наличие подтверждения;
- ограничения по количеству вызовов.

Путь к файлу и имя листа должны определяться конфигурацией приложения, а не произвольным вводом модели.

Рабочие операции допускаются только с настроенным `requests.xlsx` и листом `Заявки`.

Разрешённые пользовательские изменения:

1. Добавление одной новой заявки.
2. Изменение только статуса одной существующей заявки.

Запретить изменение заголовков, других полей существующих заявок и удаление данных.

При запрещённом вызове:

1. Не выполнять инструмент.
2. Зафиксировать отказ в журнале.
3. Передать модели сообщение с причиной отказа.
4. Разрешить корректировку действия в пределах лимитов.

### 9.1. Лимиты

- Максимум 10 рабочих MCP-вызовов на непрерывную операцию.
- Тайм-аут MCP-вызова — 15 секунд.
- Тайм-аут подключения и инициализации — 30 секунд.

Значения сделать настраиваемыми.

При превышении лимита остановить операцию и сообщить причину.

## 10. Сценарий 1 — добавление заявки

Запрос:

Ожидаемое выполнение:

3. Определяется следующий ID.
4. Контроллер проверяет обязательные поля и целевую строку.
5. Агент вызывает разрешённый инструмент записи.
6. MCP добавляет строку.
7. Через MCP выполняется повторное чтение.
8. Контроллер проверяет результат.
9. Обновляется таблица.
10. Агент сообщает итог.

Защитить приложение от повторной записи при перерисовке Streamlit.

Повторный явно отправленный пользователем запрос может создавать новую заявку.

Не объявлять успех без проверки.

## 11. Сценарий 2 — изменение статуса

Запрос:

> Измени статус заявки Анны Смирновой на «В работе».

Ожидаемое выполнение:

1. Агент читает данные через MCP.
2. Находит заявку Анны Смирновой.
3. Если найдено несколько заявок, просит уточнить ID.
4. Если заявка не найдена, сообщает об этом.
5. Показывает ID, описание, текущий и новый статус.
6. Ожидает нажатия «Подтвердить» или «Отмена».
7. Закрывает MCP-сессию на время ожидания.
8. После подтверждения открывает новую MCP-сессию.
9. Повторно читает заявку.
10. Проверяет, что исходные данные не изменились.
11. Если данные изменились, отменяет запись и запрашивает новое подтверждение.
12. Изменяет только статус.
13. Повторно читает запись через MCP.
14. Проверяет новый статус и неизменность остальных полей.
15. Сообщает результат.

Если статус уже равен целевому, не выполнять запись.

При отмене ничего не изменять.

### 11.1. Состояние подтверждения

Хранить в `st.session_state`:

- идентификатор операции;
- ID заявки;
- исходные значения;
- целевой статус;
- состояние ожидания;
- связь с записью журнала;
- признак завершения.

Разрешать только одно ожидающее подтверждение на пользовательскую сессию.

Повторное выполнение Streamlit не должно повторять подтверждённую запись.
